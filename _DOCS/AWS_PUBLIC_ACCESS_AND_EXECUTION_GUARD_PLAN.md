# AWS 공개 접속과 위험 기능 실행 보호 계획

> 작성일: 2026-07-25
> 적용 대상: `_Total`의 AWS EC2·Docker Compose 공개 배포
> 상태: **AWS 전용 코드·로컬 Docker·실제 EC2 공개 접속 검증 완료**

## 1. 목적

AllStar 대시보드와 Grafana는 수업 과제·포트폴리오 방문자가 별도 계정 없이 볼 수 있게 공개한다. 반면 외부 AI API 비용, 실제 서버 부하, 채팅 서버 중단을 발생시킬 수 있는 기능은 단순 조회 기능과 분리한다.

이 문서의 `1234` 확인은 계정 기반 보안 인증이 아니라 방문자의 실수로 위험 기능이 실행되는 것을 줄이는 **간단한 실행 잠금**이다. 공개 조회와 위험 기능 실행을 구분하는 것이 목적이며 상용 서비스의 사용자 인증 체계를 대신하지 않는다.

## 2. 공개 주소와 접속 구조

기준 도메인은 DuckDNS의 `allstarqa.duckdns.org`다.

```text
https://allstarqa.duckdns.org/
├─ /           AllStar Streamlit 대시보드
└─ /grafana/   Grafana 모니터링
```

- Caddy가 외부 HTTP·HTTPS 접속을 담당한다.
- HTTP 접속은 HTTPS로 전환한다.
- 대시보드와 Grafana 조회 화면은 누구나 접속할 수 있다.
- 전체 사이트를 막는 공통 로그인은 적용하지 않는다.
- AI·VOC API, Prometheus, K6 Runner, `service-control`은 외부에서 직접 호출하지 못하게 한다.

## 3. 외부 포트와 Docker 내부 포트

### 외부 공개

| 포트 | 공개 범위 | 용도 |
|---:|---|---|
| `80` | 인터넷 | HTTPS 인증서 발급과 HTTPS 전환 |
| `443` | 인터넷 | AllStar 대시보드와 Grafana |
| `22` | 관리자 공인 IP만 | EC2 SSH 관리 |

### Docker 내부 전용

| 포트 | 서비스 |
|---:|---|
| `8000` | AI 에이전트 API |
| `8501` | Streamlit |
| `8100` | VOC API |
| `6001~6006` | VOC 에이전트 |
| `9090` | Prometheus |
| `3000` | Grafana |
| `8200` | K6 Runner |
| `8300` | `service-control` |

로컬 개발용 `compose.yml`의 기존 호스트 포트는 유지할 수 있다. AWS에서는 별도 Compose 구성으로 외부 포트를 제거하고 Caddy와 같은 Docker 네트워크를 통한 내부 서비스명 연결만 사용한다. EC2 Security Group에서도 같은 포트를 차단해 Docker와 AWS 양쪽에서 직접 접근을 방지한다.

## 4. Grafana 공개 기준

Grafana는 포트폴리오 방문자가 로그인 없이 볼 수 있게 현재 익명 조회 방식을 유지한다.

- 익명 접근 권한은 `Viewer`로 제한한다.
- 익명 사용자는 대시보드를 조회할 수 있지만 수정·삭제·관리 설정은 변경할 수 없다.
- Grafana 관리자 암호는 AWS 환경변수로 주입한다.
- AWS에서는 기본 관리자 암호 `admin`을 사용하지 않는다.
- 브라우저 공개 주소는 `https://allstarqa.duckdns.org/grafana/`로 통일한다.
- Grafana의 직접 호스트 포트 `3000`은 인터넷에 공개하지 않는다.

## 5. 테스트 상위 탭 실행 잠금

다음 상위 탭은 기존 구현과 같이 기본 비밀번호 `1234`를 확인한 뒤 실제 화면을 렌더링한다.

1. `K6 부하 테스트`
2. `AI 에이전트 테스트케이스`
3. `VOC 테스트케이스`

잠금 해제 상태는 Streamlit의 현재 브라우저 세션에만 둔다.

- 비밀번호 원문과 해제 상태를 쿠키·URL·파일·브라우저 영구 저장소에 기록하지 않는다.
- 같은 세션의 Streamlit 재실행과 탭 이동 중에는 해제 상태를 유지한다.
- 브라우저 탭을 닫아 세션을 끝내거나 Streamlit 서버를 재시작하면 다시 잠근다.
- 서로 다른 브라우저와 사용자는 해제 상태를 공유하지 않는다.
- 오답이면 실제 기능을 렌더링하지 않고 재입력 안내를 표시한다.

## 6. AI 챗봇 장애 상황 시험 잠금

AI 에이전트 일반 챗봇은 공개 상태를 유지한다. 채팅 입력창 아래의 장애 상황 시험은 별도 잠금 영역으로 구분한다.

### 잠금 상태

```text
장애 상황 시험

실제 채팅 서버의 장애 상황을 재현하는 기능입니다.
서비스 중단과 시험 로그가 발생하므로 비밀번호 확인 후 사용할 수 있습니다.

[ 비밀번호 입력 ] [ 확인 ]
```

- 비밀번호 확인 전에는 장애 시험 버튼 3개를 표시하지 않는다.
- 입력란은 마스킹한다.
- 오답이면 `비밀번호가 올바르지 않습니다. 다시 입력해 주세요.`라고 표시한다.
- 일반 챗봇 대화 기능은 잠그지 않는다.

### 해제 상태

`1234`를 확인하면 현재 브라우저 세션에서만 다음 버튼을 표시한다.

1. `503 서비스 이용 불가 시험`
2. `504 시간 초과 시험`
3. `채팅 서버 중단 시험`

해제 상태는 테스트 상위 탭과 마찬가지로 영구 저장하지 않는다. 브라우저 탭을 닫아 세션을 끝내거나 Streamlit 서버를 재시작하면 다시 비밀번호를 확인한다.

장애 시험은 기존 기준에 따라 실제 대화·운영 로그에 기록하지만 AI 답변 품질 실패로 계산하지 않고 `N/A`로 처리한다.

## 7. `service-control` 보호 경계

`service-control`은 AI·VOC 채팅 API 컨테이너를 실제로 중단하고 재시작하는 장애 시험·재접속 기능을 위해 유지한다.

### 허용 범위

| 서비스 | 시작 | 중단 |
|---|---:|---:|
| `portfolio-api` | 허용 | 허용 |
| `voc-api` | 허용 | 허용 |

- 임의 서비스명, 컨테이너 ID, Docker 명령 문자열을 입력으로 받지 않는다.
- 현재 Compose 프로젝트 라벨과 허용된 서비스 라벨을 모두 확인한다.
- 요청·성공·실패와 실제 결과 상태를 서비스 로그에 기록한다.

### AWS 보강 구현

- `service-control` 호스트 포트를 공개하지 않는다.
- Streamlit과 `service-control` 사이의 요청에 내부 전용 토큰을 사용한다.
- 내부 토큰이 없거나 일치하지 않으면 상태 변경 요청을 거부한다.
- 내부 토큰은 Git과 Docker 이미지에 넣지 않고 EC2 환경변수로 주입한다.
- Streamlit과 다른 앱 컨테이너에는 Docker 소켓을 연결하지 않는다.
- Docker 소켓은 `service-control`에만 연결하고 기존 서비스 허용 목록을 유지한다.

Docker 소켓은 호스트 Docker Engine을 제어할 수 있는 강한 권한이다. 현재 수업 과제의 Docker Compose 구조에서는 위와 같이 외부 접근 차단, 내부 토큰, 고정 허용 목록, 감사 로그를 함께 적용해 위험을 줄인다.

## 8. 비용·부하 기능 추가 보호

화면 비밀번호만 신뢰하지 않고 실행 상태도 서버에서 검사한다.

- 외부 API 호출 또는 실제 부하 발생 가능성을 실행 전에 안내한다.
- 필수 확인 체크박스를 유지한다.
- 동일 시험의 중복 실행을 막는다.
- 동시에 하나의 고부하 시험만 실행한다.
- 시험 진행 중에는 충돌하는 실행 버튼을 비활성화한다.
- 실행 중지 기능과 종료 상태 기록을 유지한다.
- 화면을 조작하거나 새로고침해도 이미 실행 중인 시험을 중복 시작하지 않는다.

## 9. 비밀값 관리

다음 값은 Git, Docker 이미지, 보고서, 일반 로그에 기록하지 않는다.

- OpenAI API 키
- Anthropic API 키
- DuckDNS 토큰
- Grafana 관리자 암호
- `service-control` 내부 전용 토큰

비밀값은 EC2의 별도 환경 파일로 주입하고 접근 권한을 제한한다. 기본 실행 잠금값 `1234`는 사용자 요청에 따른 포트폴리오용 단순 잠금값이며 비밀 인증정보로 취급하지 않는다.

## 10. DuckDNS와 S3 보호 기준

### DuckDNS

- EC2 시작 시 현재 공인 IPv4를 `allstarqa.duckdns.org`에 갱신한다.
- DuckDNS 토큰을 갱신 로그에 출력하지 않는다.
- DNS 주소가 현재 EC2 공인 IP와 일치하는지 확인한다.

### S3

- 퍼블릭 접근을 차단한다.
- 버전 관리와 서버 측 암호화를 활성화한다.
- EC2 IAM 역할을 사용해 업로드한다.
- 하루 한 번 변경된 로그·보고서를 동기화한다.
- EC2 시작 시 누락 동기화를 확인하고 종료 전 최종 동기화를 수행한다.
- API 키와 환경 파일은 S3 동기화 대상에서 제외한다.

## 12. 구현과 검증 상태

2026-07-25에 다음 AWS 전용 항목을 구현했다.

- `compose.aws.yml`에서 기존 공개 포트를 제거하고 Caddy의 `80`·`443`만 공개
- Caddy 자동 HTTPS와 `/`, `/grafana/` 프록시
- Prometheus·Grafana·Caddy·`_OUTPUT`의 EBS 영구 경로
- `service-control` 상태·시작·중단 요청의 내부 토큰 인증
- IMDSv2 기반 DuckDNS 시작 시 갱신
- S3 하루 1회 변경 동기화, 부팅 보완, 종료 전 최종 동기화
- 종료 전 Prometheus 스냅샷·압축·SHA-256 체크섬
- EC2 Docker·AWS CLI 설치와 systemd 시작·종료·배포 자동화

로컬 Docker에서는 Caddy 경유 대시보드와 Grafana HTTP `200`, Caddy 외 호스트 포트 미공개, 내부 토큰 `401/401/200`, Prometheus 스냅샷을 확인했다. 실제 EC2에서는 IMDSv2 기반 DuckDNS 갱신, Caddy 공개 HTTPS 대시보드·Grafana `200`, S3 실제 업로드, S3 버전 관리·SSE-S3·퍼블릭 접근 차단을 확인했다. EC2 중지·재시작 후 자동 복구와 Prometheus 보존 검증은 남아 있다. 상세 명령과 결과는 `AWS_EC2_DOCKER_DEPLOYMENT_RUNBOOK.md`를 따른다.
