> 적용일: 2026-07-25
> 구현 상태: AI 에이전트·VOC 활성 테스트케이스 각 3건 적용 완료
> 목적: AWS 포트폴리오 시연에서 전체 실행과 보고서 생성을 짧은 시간 안에 재현

## 현재 실행 범위

QA 컨트롤러와 통합 대시보드의 전체 실행은 고정 숫자를 사용하지 않고 각 `test_cases.json`의 현재 등록 목록 전체를 읽는다. 현재 활성 범위는 다음과 같다.

### AI 에이전트 3건

| ID | 유형 | 확인 목적 |
|---|---|---|
| `TC-001` | Happy | 교육과정 지식의 정상 답변과 정확성 |
| `TC-021` | Edge | 문서에 없는 질문의 안전한 거절 |
| `TC-026` | Negative | 위협·폭력 요청의 안전한 거절 |

활성 파일은 `src/allstar/ai_agent/evaluation/test_cases.json`이다. 축소 직전 6건 원본은 `src/allstar/ai_agent/evaluation/archive/test_cases_6_2026-07-25.json`에 보존한다.

### VOC 3건

| ID | 유형 | 확인 목적 |
|---|---|---|
| `TC-01` | 일반 VOC | 관련 VOC 검색·요약·원인·개선안 생성 |
| `TC-04` | 오타 질문 | 오타와 띄어쓰기 오류가 있는 고객 발화 이해 |
| `TC-09` | 데이터 없음 | Retriever 0건을 정상 예외로 처리하고 허위 답변을 만들지 않는지 확인 |

활성 파일은 `src/allstar/voc/evaluation/test_cases.json`이다. 축소 직전 10건은 `src/allstar/voc/evaluation/archive/test_cases_10_2026-07-25.json`, 최초 20건은 `src/allstar/voc/evaluation/archive/test_cases_20_2026-07-17.json`에 보존한다. 기존 ID를 유지해 과거 로그·보고서와 사례를 연결할 수 있게 했다.

## 화면과 보고서 동작

- AI 에이전트 테스트케이스 실행은 현재 3건을 API 방식과 규칙 기반 방식으로 각각 처리한다.
- VOC A·B·C·D 실행은 선택한 프로필로 현재 3건을 처리한다.
- 실행 전 확인 상자의 전체 범위와 예상 호출 범위는 파일을 다시 읽어 자동 계산한다.
- 테스트케이스 관리 화면에서 사례를 추가·수정·삭제하면 다음 실행 범위도 함께 바뀐다.
- 최신 정식 보고서는 현재 등록된 전체 3건이 정상 완료됐을 때만 새 결과로 교체한다.
- 기존 6건·10건 보고서와 실행 로그는 당시 범위의 이력으로 보존한다. 새 3건 전체 실행 전까지 화면에 보이는 과거 최신 보고서가 6건·10건 기준일 수 있다.
- A~D 종합 발표자료는 현재 활성 사례 수와 ID를 동적으로 읽으며, 과거 10건 결과와 현재 3건 정의를 섞어서 생성하지 않는다.

## 검증 원칙

- 이번 범위 변경 자체에서는 외부 AI API를 호출하지 않는다.
- JSON 구조, 아카이브 보존, 동적 실행 범위와 보고서 문구를 비API 자동검사로 확인한다.
- AWS 시연 전 실제 전체 실행은 사용자가 화면에서 비용 가능성을 확인한 뒤 진행한다.
- 실제 3건 결과가 정상 완료되면 해당 실행부터 최신 정식 보고서와 A~D 종합 비교의 새 기준이 된다.
